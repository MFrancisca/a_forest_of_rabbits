  <action>
Create the `docs/` directory and write `docs/migration-guide.md` as a step-by-step migration guide. The guide is written for the site owner performing the migration once, in order. It must be concise — the owner will read it during actual work, not as background reading.

Structure the guide with these exact sections:

**Prerequisites (check before starting)**
- Dev server must be running: `docker compose up`
- Projects index page must exist: `curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/projects/` must return 200. If 404, run: `docker compose exec web python manage.py create_site_skeleton`
- Have the live Google Sites open in a browser tab alongside the Wagtail admin

**Step 1: Create the three Category snippets FIRST**
- Navigate: /cms/ > Snippets > Categories > "+ Add Category"
- Create: "Calligraphy & Illumination", then "Clothing", then "Armor"
- Do this before touching any articles — you cannot assign a category to an article that does not exist yet

**Step 2: For each article, repeat these sub-steps**

Step 2a — Download images from Google Sites
- For each image in the article: right-click > Save image as — save to a local folder
- Do this for ALL images before starting the Wagtail entry

Step 2b — Upload images to Wagtail image library
- Navigate: /cms/ > Images > "Add an image"
- Upload each saved image file; give it a meaningful filename (becomes searchable)
- You can upload all images for an article in one batch before creating the page

Step 2c — Create the ProjectPage
- Navigate: /cms/ > Pages (sidebar) > Root > Projects > "+ Add child page" > "Project page"
- Fill in: Title (copy from Google Sites heading), Date (original date if visible; today's date otherwise), Category (select from dropdown), Excerpt (short description — first sentence or two)
- **Leave the Cover Image field BLANK** — all images go inline in the body

Step 2d — Add body text
- In the Body editor: paste the article text from Google Sites
- Apply headings (H2, H3), bold, italic, lists using the toolbar as needed
- Minor formatting differences from Google Sites are acceptable

Step 2e — Insert images inline in the body (MOST IMPORTANT STEP)
- Position your cursor in the body text where the image should appear
- Click the image toolbar button (picture icon)
- In the chooser modal: search for the image you just uploaded by filename
- Select it; choose "Full width" or the desired format
- Click Insert — the image appears in the body at the cursor position
- Repeat for each image in the article

Step 2f — Publish
- Click "Publish" (not "Save draft") — draft articles do NOT appear on /projects/
- Verify: visit http://localhost:8000/projects/ and confirm the new article appears in the list
- Click through to the article; confirm all images display (not broken)

**Step 3: Update the checklist**
- Open `docs/migration-checklist.md`
- Fill in the row for this article: tick the Done box, add the Article Title, Category, and Wagtail URL (e.g. `/projects/making-oak-gall-ink/`)
- Save the file

**Step 4: After ALL articles are complete**
- Commit the completed checklist: `git add docs/migration-checklist.md && git commit -m "docs(05): complete content migration checklist"`
- The checklist must be 100% ticked before Phase 6 DNS cutover begins
