# Plan 01-02 Summary: Pigment Models + Wagtail Admin

## What Was Built

All 11 pigment data models in `pigments/models.py` using Wagtail Snippets with ClusterableModel and InlinePanel for nested admin editing. Initial migration generated and committed.

## Key Files

### Created
- `pigments/models.py` — 11 models: ColorFamily, PigmentFamily, Country, Brand, Paint, Manuscript, Pigment (ClusterableModel), Formula (ClusterableModel+Orderable), FormulaPart (Orderable), PigmentManuscript (Orderable), PigmentImage (Orderable)
- `pigments/wagtail_hooks.py` — confirms hooks module loads; models registered via @register_snippet decorator
- `pigments/migrations/0001_initial.py` — generated by Django, covers all 11 models
- `pigments/migrations/__init__.py`

## Decisions Made

- `Pigment` and `Formula` are both `ClusterableModel` for two-level nesting (Pigment → Formula → FormulaPart via InlinePanel)
- Child models use `ParentalKey`, not `ForeignKey`
- `PigmentImage.image` is nullable (`null=True, blank=True`) so Phase 1 factories work without Wagtail image fixtures
- Brand and Paint models added (not in original 11 count but needed by Formula/FormulaPart relationships)
- Migration generated with `DJANGO_SETTINGS_MODULE=config.settings.dev` via local venv (Docker not available in this environment)

## Requirement Coverage

- PIGM-04: ColorFamily, PigmentFamily, Country, Manuscript registered as Wagtail Snippets — owner can create/edit/delete from /cms/ admin without touching code
